# PwC One Assistant

Enterprise MCP-based assistant that answers only from approved documents and gates every write behind human approval.
Design: [design.md](design.md). Engineering rules and commands: [CLAUDE.md](CLAUDE.md).

## Quick start

```bash
uv sync
cp .env.example .env          # set OPENROUTER_API_KEY for model answers (without it, answers are extractive)
uv run pytest tests/          # unit, integration and safety tests
uv run uvicorn app.main:create_app --factory --env-file .env --reload   # API
uv run streamlit run ui/chat.py        # chat page
uv run streamlit run ui/workbench.py   # developer workbench (six tabs)
```

## Layout

| Path | Purpose |
|---|---|
| `app/` | API (FastAPI), agent loop, triage, retrieval wiring, verifier, LLM clients (OpenRouter, optional Groq fallback), storage, cache, telemetry, settings |
| `plugins/` | PII redaction, injection shield, ambiguity and authentication gates, loop and failure breakers, idempotency, RAGAS auditor, model fallback |
| `mcp_servers/` | MCP servers: `rag_mcp.py`, `graphify_mcp.py` (stdio), `state_mcp.py` (Streamable HTTP), `k6_mcp.py`; plus the retrieval library `rag_server.py` and ONNX model wrappers |
| `ui/` | Streamlit pages: `chat.py` (chat with live metrics), `workbench.py` (six developer tabs), `style.py` (shared theme) |
| `knowledge/` | Approved policy notes with frontmatter and wikilinks. Synthetic and PII-free; generated by `scripts/build_vault.py` |
| `data/` | Test data: `golden/` (250 retrieval questions), `labels/` (hand-labelled verifier answers), `redteam/` (100 adversarial prompts) |
| `evals/` | Runners only: golden evaluation with per-failure diagnostics, threshold sweep, verifier calibration, red team, 36-KPI scorecard |
| `evals/results/` | Generated results (not tracked) |
| `scripts/` | Vault build, local load runner, Claude Code hooks |
| `load_tests/` | k6 scenarios (smoke, load, isolation, soak) |
| `docs/` | Design deep-dives; `docs/archive/` holds earlier Word documents |
| `second-brain/` | Project and session notes, kept separate from production retrieval |
| `mcp_config.json` | Servers, plugins, retrieval thresholds, bulkheads, governance versions (validated by `app/mcp_config.py`) |

## Configuration

Settings come from `.env` (see `.env.example`). Main options:

- `RETRIEVAL_BACKEND=onnx` activates the pinned BGE encoder and reranker. Without it, lightweight stand-ins are used.
- `DATABASE_URL`: `sqlite:///./dev.db` for development; production requires `postgresql://...` and refuses to start otherwise.
- `CACHE_BACKEND=redis` with `REDIS_URL` enables the Redis cache; the default is in-process.
- `GROQ_API_KEY` and `GROQ_MODEL` enable a fallback model used only after OpenRouter fails. Blank means disabled.
- `APPLICATIONINSIGHTS_CONNECTION_STRING` or `OTEL_EXPORTER_OTLP_ENDPOINT` enable telemetry export.

## Evaluation

```bash
uv run python -m evals.run_golden --llm --subset --small-only   # token-capped calibration sample
uv run python -m evals.verifier_calibration                     # verifier on labelled answers (no model calls)
uv run python -m evals.threshold_sweep                          # retrieval threshold trade-off (no selection)
uv run python -m evals.redteam                                  # adversarial suite (target: 0 misses)
```

The threshold sweep reports trade-offs only. Changing `retrieval.reranker.min_score` in `mcp_config.json` is a human decision.

## Known limits

- The retrieval and answer checks are still being calibrated, and the verifier is strict. Expect abstentions on paraphrased answers.
- The approved knowledge base is synthetic demo content that has not been reviewed by the organization.
- Golden-set questions were generated by a model and have not been reviewed.
- The package is still named `app`; a rename to `src/pwc_one` is planned as a separate change.
